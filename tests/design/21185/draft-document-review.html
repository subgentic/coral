Release plan

Design notes · current delivery paths and proposed behavior

Today: where comments reach the agent

  1. Inbox document viewer: Comment and Reply save through POST /api/artifacts/{id}/comments. Owner comments automatically notify the uploader; replies target agents already in the thread. A busy agent’s message can be held until free. Editing/deleting does not retract a notification already sent.
  2. Explicit Send to agent: individual threads can be sent to selected agents; “Send N open comments” uses bundle/last to deliver together. Existing bundles over the message-size cap split into multiple messages. Time-anchored video comments already set notify_agent:false.
  3. Through a Hub: comment_writes gates writing; comment_send separately gates manual sending. When writing is enabled, a normal owner save can still follow the server’s automatic delivery path. Without write capability, comments are read-only. This design must never fall back to automatic notification when Send is unavailable.
  4. Decisions: Request changes creates/sends a whole-document comment; Approve (including its optional note), Deny and other review notices have their own decision notifications. Unfinished composer text already has an approval warning; it is not a durable review batch.
  5. Google Docs, behind its share/sync switch: new Google comments and replies are mirrored onto the latest artifact version and noteGdocComment delivers them through the board path; no-team files type a notice into the uploader session. Agent replies/resolutions can sync back. Google has no Coral “Send comments” action today.
  6. Other callers: CLI/API comment/reply creation uses the same server delivery rules unless notify_agent:false. No-team artifact comments deliver to the uploader session. Goal/diff comments have separate targets and are outside this document-review mock.

Proposed review contract

Drafts belong to the reviewer, computer and exact document version. They persist across closing/reopening and are visible only to that reviewer until sent. Saving/editing/deleting a draft never notifies an agent. Replies follow the same rule. Existing published threads remain readable.

Send comments publishes a snapshot of all pending comments/replies as one review message with document/version, quote or whole-document anchor, comment body and thread reply references. A failed send keeps drafts; ambiguous outcomes must be checked before retry so the batch is not duplicated. Busy-agent queueing is a successful send, shown as “Queued”, not “Draft”. A batch too large for one message needs an explicit limit or a single linked review summary, not silent splitting.

Approve / Request changes offer to include all drafts in the same decision delivery. Going back keeps drafts; drafts cannot be silently lost or sent separately on save. Cross-device draft storage, atomic send/decision behavior and sender permissions need a backend contract before implementation.

For Google Docs, import feedback as a pending review in Coral, mark its Google source, and let the reviewer send the batch from Coral. The mock names this change explicitly: Google authors cannot trigger Coral’s send directly from Google. Hub send restrictions remain visible.
