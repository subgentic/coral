Review notes
  1. Request → Allow → code → connected. Allow prepares the connection; it completes only when this code is entered into the requesting Hub. The existing Home Hub connection stays in place.
  2. Identity and access stay visible. The full HTTPS address is shown without truncation. Launch uses Coral’s existing access wording. A real card must show the actual access requested and target computer.
  3. Denied and expired are separate outcomes. Neither shows an active code. A new request starts from Add computer on the requesting Hub; there is no silent retry or renewed permission.
  4. Illustrative protocol values. The eight-digit code and five-minute countdown are samples, pending #20901 and Security review. This mock makes no promise about code length, lifetime or owner verification.
  5. Coral side only. SSH and HTTP arrive at this same card. Hub B’s Add computer / enter-code screen belongs to the Hub team. Static sample countdown; no network, link changes or real credentials.
