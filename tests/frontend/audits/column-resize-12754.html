Dashboard column resize audit · #12754

Inspected base 30df0983f, 2026-11-02. Source inventory: 27 modules, 39 shared table call sites. This is a source audit; live resize proofs follow with the implementation.

Main finding

All dashboard data tables already use data_table.js, directly or through wrappers. Both the table census (zero legacy builders, zero legacy table styling) and table inventory pass. The gap is the shared component: oneLine: true forcibly disables resize, skips saved-width loading, and skips the layout used by the resize handlers. Artifacts additionally sets resize: false. Thus this is shared resize support for existing tables, not a migration from independent table renderers.

Existing shared contract

  • One 10px separator hit area; divider visible on header hover, focus, or drag. Keyboard focus outline is shared.
  • Drag; Left/Right moves 16px (Shift: 48px); Enter and double-click fit content. Dragging does not sort.
  • Widths saved in guarded browser storage under coral-dt-widths:<widthsKey or label without count>. Elastic primary width follows the others; fixed controls are not stored. Group labels determine grouped-list keys.
  • Widths fit the available box and optional columns yield by priority. Fixed action columns and the last visible movable column have no handle. A one-column table has no movable edge.
  • Folded rows and viewports at most 767px wide have no handle. Landscape phone handling needs to remain consistent with the phone layout definition. Phone mail/card rendering and one-line dropAt priorities must remain.

Other dashboard lists

Agents home/sidebar are lists/cards, not column tables; the team Agents table is listed above. Settings fields, computer/connection cards, worktree lists and similar settings lists are forms/cards, not independent HTML tables. Registered computers wraps server_table.js and is counted above. Team artifacts, agent artifacts, task/goal artifact sections and Inbox artifacts share artifact_table.js. Author-written Markdown tables in chat/Docs/previews are the sole content-table exemption; they are content, not dashboard data-list controls. Session tooltips are facts lists.

Implementation order

  1. Artifacts first: add shared one-line resize support while retaining sort, density, dropAt priorities, saved widths and phone layout; exercise Inbox/team artifact table entry points.
  2. Enable the remaining one-line tables through the same shared path, retaining per-surface columns and sort. Explicit opt-outs occur in artifact_table.js, mailbox_starred_artifacts.js and mailbox_chats.js; implicit opt-outs are listed above.
  3. Exercise drag, remembered widths, keyboard and fit behavior in the shared resize suite plus surface checks; keep 390px no-handle checks. Run table census, inventory, table_rules shape/live checks, and affected golden/pin/phone cases.

Coordination question: the task requests one commit per table. Because most gaps are the same shared oneLine switch, recommend a shared support commit with surface opt-ins as separate commits, starting with Artifacts, rather than unrelated renderer replacements. Preserve intentional fixed and last-column exclusions.
